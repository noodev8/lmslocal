# =============================================================================================
# THE SAME LINES, WITH THE REASONING - reference, not for pasting
# =============================================================================================
#
# WHY THE ORDER MATTERS. Magic send (services/emailQuiet.js) marks anyone emailed in the last 48
# hours as sent rather than emailing them again, so whichever email runs first takes the collisions
# and the ones after it get whoever is left. Nothing is exempt: moving a line up is the only way to
# promote an email, and there is no priority setting in the code, on purpose.
#
# A '#' switches one off - no edit, no commit, no deploy, no restart. `crontab -l` is the only
# honest answer to what is running; the admin screen cannot see this file.
#
# DRY RUN BEFORE SWITCHING ONE ON, especially with a backlog behind it. The kill is permanent:
#   node scripts/email-sweep.js <type> --dry-run     lists who qualifies, marks declines with [48h]
#   node scripts/email-sweep.js <type> --test        one sample to the test address, writes nothing
#
# The order here is a STARTING SUGGESTION, not a finding. It ranks by how much damage a killed
# email does, and by whether losing it is permanent (once-ever) or merely a deferral (a recurring
# nudge that comes round again). Real sends will beat that reasoning - move things as you learn.
